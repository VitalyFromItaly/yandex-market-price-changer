# Веб-приложения (`web/`)

Все браузерные SPA проекта лежат здесь, каждое в своей папке `web/<app>/`. Бэкенд — в `src/`, его
раздаёт тот же Nest-процесс: одна репа, один образ, один домен.

| Папка | Что это | URL | README |
|---|---|---|---|
| `web/admin/` | Админ-панель (журнал действий, доступы, очереди, ИИ…) | `/` | `web/admin/README.md` |
| `web/crm/` | CRM продавца (MarketHub) | `/crm/` | `web/crm/README.md` |

У приложений нет своих `package.json` и `node_modules`: зависимости и скрипты живут в корне.
Свой у каждого только `vite.config.ts`, а при необходимости ещё `tsconfig.json` и `vitest.config.ts`.

## Правила

- **Новое веб-приложение — только новая папка `web/<app>/`.** Рядом с `src/` и в корне их не кладут.
- **Код бэкенда приложения берут из `src/shared/` относительным импортом.** Глубина пути
  `../../../../src/shared/...` зависит от вложенности. Импорт из `src/modules/**` запрещён:
  туда тянется Nest. Если приложение импортирует из `src/`, его дев-серверу Vite нужен
  `server.fs.allow: ['../..']`, чтобы разрешить чтение выше `web/<app>/`.
- **Конфиги задаются явно в `vite.config.ts` каждого приложения.** Файлов `postcss.config.*`,
  `tailwind.config.*` и подобных в самой `web/` нет: Vite ищет их вверх по дереву, и один такой
  файл подхватили бы все приложения сразу.
- **Каждое приложение — SPA на hash-роутере.** Nest отдаёт статику без SPA-fallback.
  Не корневое приложение собирается с `base: '/<app>/'`.

## Как добавить приложение `web/<app>/`

1. Создать `web/<app>/` с `index.html`, `src/` и `vite.config.ts`. В конфиге задать `root` от своей папки,
   `base: '/<app>/'`, `outDir: 'dist'` и свой порт dev-сервера с proxy `/api` → `:3004`.
2. В корневом `package.json` добавить скрипты:
   - `dev:<app>` и `build:<app>` с `--config web/<app>/vite.config.ts`;
   - вызов `build:<app>` в `build`;
   - если у приложения есть свой tsconfig или тесты — ещё `typecheck:<app>`/`test:<app>` и их шаги в
     `.github/workflows/nodejs.yml`.
3. В `src/main.ts` добавить `useStaticAssets(join(__dirname, '..', 'web', '<app>', 'dist'), { prefix: '/<app>' })`.
   Регистрировать **до** корневой админки: express-static отдаёт первый найденный файл.
4. В `Dockerfile` (runner-стадия) добавить `COPY --from=builder /app/web/<app>/dist ./web/<app>/dist`. Исходники
   уже копирует общий `COPY web ./web`.
5. В `eslint.config.js` решить, линтуется ли приложение. Если нет — добавить `web/<app>/**` в
   `ignores`, как у admin. Если да — завести блок `files: ["web/<app>/**"]`, как у crm.
   Широкий глоб `web/**` в ignores не использовать: он скроет CRM.
6. Добавить строку в таблицу выше, `web/<app>/README.md` и строку в карту документации в `CLAUDE.md`.
