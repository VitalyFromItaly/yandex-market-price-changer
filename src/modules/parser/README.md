# 📄 Модуль parser — вне живого пути

> **Этот модуль не участвует в работе бота.** Живой разбор прайса — в
> [`src/modules/yandex/stocks/price-list.parser.ts`](../yandex/stocks/price-list.parser.ts). Читать
> дальше стоит только если вы решаете судьбу этого кода: удалить, или что-то из него забрать.

## Почему он мёртв

Модуль писался под цепочку обновления цен: файл → парсинг → сравнение с Маркетом → запись новых цен и
создание карточек. Изменение цен по API прекращено решением заказчика при переходе на NestJS, и вместе
с ним обесточилась вся цепочка Bull.

Единственный, кто отсюда импортирует, — `telegram/services/file-data-processor.service.ts`, а он сам
вызывается только из мёртвых обработчиков очереди. То есть из `main.ts` этот код недостижим. Ещё есть
ручной вход `npm run parser:run` (`run-simple-parser.ts`), которым парсер запускали по локальному файлу.

## Чем живой парсер отличается

Не «лучше» — он решает другую задачу, и решает её узко.

|           | `parser/` (мёртвый)                       | `yandex/stocks/price-list.parser.ts` (живой)                                       |
| --------- | ----------------------------------------- | ---------------------------------------------------------------------------------- |
| Форматы   | Excel и CSV, автоопределение              | только Excel                                                                       |
| Колонки   | угадываются по названиям в шапке          | фиксированная раскладка: `B` наименование, `E` цена, `G` количество                |
| Артикул   | извлекается регулярками из наименования   | не извлекается; сопоставление отдельным шагом (`sku-resolver`) по каталогу Яндекса |
| Кодировки | UTF-8 / Windows-1251, лечение «кракозябр» | не нужны: xlsx хранит текст в UTF-8                                                |

Угадывание колонок и извлечение артикулов регулярками — ровно те два места, которые в живом коде
делаются иначе и намеренно. Про регулярки история записана в `sku-resolver.ts`: прежний набор из
двенадцати шаблонов давал на «Командирские 350501 К-35» артикул «К-35», одинаковый для одиннадцати
разных часов, — остатки писались бы в одну карточку, последний затирал бы предыдущих, молча.

## Что здесь есть

```
parser/
├── constants/sku-patterns.ts   шаблоны для вытаскивания артикула из наименования
├── domain.parser.ts            типы разобранной строки
├── encoding-fixer.ts           определение и починка кодировок (нужно только для CSV)
├── parser.ts                   парсер с автоопределением формата и колонок
├── simple-parser.ts            упрощённый: читает лист xlsx по позициям колонок
├── run-simple-parser.ts        ручной запуск: npm run parser:run
└── prices.xlsx                 пример файла (594 КБ, отслеживается в репозитории)
```

`encoding-fixer.ts` — единственная часть, которая может понадобиться снова: если прайс когда-нибудь
начнёт приходить в CSV, лечение Windows-1251 придётся написать заново. Остальное дублирует живой путь.

## Если удалять

Удалять вместе с мёртвой цепочкой Bull, а не отдельно: `file-data-processor.service.ts`, обработчики
`queue/processors/file-processing.processor.ts` и `yandex-api.processor.ts`,
`handlers/file-upload.handler.ts` и скрипт `parser:run` в `package.json`. Пользовательские тексты в тех
файлах (про коэффициент цен, CSV, «Скачать пример») выглядят живыми — их не надо править, они должны
уйти вместе с кодом.
