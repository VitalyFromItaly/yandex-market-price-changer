# Модуль imaging — сборка карточек товара

Берёт фото часов на белом фоне (как их присылает поставщик), вырезает объект и
ставит его в фирменную тёмную сцену с тенью и отражением.

Модуль пока **вне живого пути бота**: работает только через CLI. Ядро написано
чистыми функциями именно для того, чтобы подключение к боту не потребовало
переписывания.

## Зависимости — только для разработки

`onnxruntime-node` и `sharp` лежат в **devDependencies**, а сам каталог исключён
из `tsconfig.build.json`. То есть в прод-образ не попадают ни пакеты, ни
`dist/modules/imaging`: работать там модулю всё равно нечем — `assets/` в образ не
копируется, а веса (170 МБ) в git не хранятся. Заодно это убрало из сборки 258 МБ
бинарников onnxruntime и докачку CUDA EP с nuget.org, на которой 05-08-2026 упал
деплой.

Отсюда два следствия:

- локально нужен полный `npm ci` (без `--omit=dev`), иначе команды ниже не
  запустятся;
- **при подключении модуля к боту оба пакета придётся вернуть в `dependencies`**,
  убрать строку из `exclude` и добавить `COPY assets` в `Dockerfile`.

## Команды

```bash
npm run image:fetch-model        # один раз: скачать веса (~170 МБ)

npx ts-node scripts/compose-product-image.ts --in=photos/ --out=cards/
npx ts-node scripts/compose-product-image.ts --in=g-shock.jpg --out=cards/ --debug
```

`--in` принимает файл или каталог (без рекурсии). Прочие аргументы описаны в
шапке `scripts/compose-product-image.ts`.

## Как это работает

```
фото на белом
  ├─ background-removal.service  isnet-general-use (ONNX) → маска
  ├─ mask-refine                 снятие каймы фона, подрезка хвостов маски
  ├─ geometry                    вписывание в бокс, посадка на линию контакта
  └─ scene-composer              фон → тень → отражение → товар
готовая карточка
```

### Почему модель, а не порог по белому

Чисто алгоритмический порог хорошо режет чёрный G-Shock и разваливается на
стальном браслете: блики на полировке по яркости неотличимы от фона, а просветы
между звеньями надо вычищать отдельно от внешнего контура.

Модель здесь **дискриминативная**: отвечает «объект или фон» и ничего не
дорисовывает. Генеративная («улучшить фото») для товарной карточки не подходит —
она способна незаметно переписать надписи на циферблате, и брак обнаружится уже
у покупателя.

### Почему кайма снимается формулой, а не подрезкой маски

Краевой пиксель исходника — смесь объекта с фоном. На белом фоне это незаметно,
на тёмной сцене превращается в светящийся контур. Фон известен, поэтому смесь
разбирается точно: `F = (C − BG·(1 − α)) / α`. Ореол не маскируется, а
вычитается. Подробности — в шапке `mask-refine.ts`.

### Что задаётся пресетом, а не кодом

Фон — расходник. Второй шаблон означает второй JSON в `assets/scenes`, а не
правку композитора. Все доли считаются от размера канвы, чтобы пресет пережил
замену шаблона на тот же кадр в другом разрешении. Схема и значения по
умолчанию — в `scene-preset.ts`; неизвестные ключи отвергаются, чтобы опечатка
не выглядела как «параметр почему-то дефолтный».

Отдельно про `reflection.maxHeight`: длина отражения считается от товара, а
глубина подиума от товара не зависит. Без потолка высокие часы на ремешке дают
отражение, съезжающее с подиума на фон.

## Грабли, на которые уже наступили

- **sharp отдаёт одноканальный raw в трёх каналах.** Маска на выходе `resize`
  разворачивается в sRGB, буфер выходит втрое длиннее объявленного, строки
  разъезжаются — маска приходит в полоску с расползающимся веером, и виноватыми
  выглядят модель и препроцессинг. Лечится `toColourspace('b-w')`; длина
  результата проверяется явно, чтобы в следующий раз это падало, а не косило
  картинку. `extractChannel('alpha')`, наоборот, один канал и отдаёт.
- **Размытая тень срезается по краю собственного холста.** sharp размывает в
  пределах картинки, поэтому холст расширяется на три сигмы ДО `blur`, а вылезшее
  за канву отрезает `clipToCanvas` — сдвигать слой внутрь нельзя, тень уехала бы
  из-под товара.
- **Полупрозрачный лоскут белого фона там, где модель не уверена**, читается на
  тёмной сцене как светлый призрак. Срезается порогом `--alpha-floor` (0.2–0.3);
  платой идёт чуть более резкий край. Смотреть удобно вместе с `--debug`, который
  кладёт рядом маску и вырезанный объект.
- **Константы препроцессинга сверены с исходниками rembg**, а не написаны по
  памяти: ошибка в mean/std не роняет запуск, она молча портит маску.

## Веса модели

`assets/models/` в `.gitignore` — 170 МБ в репозиторий не едут.

**При переезде в бота качать в рантайме нельзя.** Прод стоит на российском
хостинге, где внешние домены недоступны так же, как `api.telegram.org` (ровно
поэтому в проекте есть `TELEGRAM_API_URL`). Файл должен попадать в образ через
`COPY` на этапе сборки.

## Что нужно для запуска

Только веса: `npm run image:fetch-model`. Фон и пресет лежат в `assets/scenes/`
и в репозиторий входят — 2 МБ, зато модуль работает из свежего клона. CLI
проверяет наличие и фона, и модели до обхода файлов и говорит, чего не хватает.

Числа пресета подобраны **глазами под этот шаблон** (`anchor.y` = линия контакта
на верхней плоскости подиума) и проверены на живом фото G-Shock. Для другого фона
их придётся подбирать заново: где именно поверхность, видно только на картинке.
Удобно так — сделать несколько JSON с разными `fit`/`anchor` и прогнать одно фото
через каждый, сравнив результаты рядом.

## Подключение к боту

Сейчас модуль — набор функций и класс без декораторов. Для бота понадобится:
обернуть в `@Injectable()` + `ImagingModule`, держать `BackgroundRemover`
синглтоном (сессия ONNX загружается один раз) и увести обработку в очередь Bull —
она упирается в процессор и в хендлере будет держать бота.
