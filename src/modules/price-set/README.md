# Установка цен (M28, TASK-199…203)

Запись цен продажи на ЯМ, Ozon и WB со страницы CRM: наценка от закупа последнего прайса (свой % на площадку)
или файл «артикул | цена». Продавец видит план «было → станет» по каждой площадке, снимает лишние строки и
подтверждает запись.

| Файл                                                                         | Что                                                                                  |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `price-set.domain.ts`                                                        | лист: план по площадкам, пропуски, блокировки, риск, отпечаток (`priceSetPlanOf`)    |
| `price-set-file.ts`                                                          | разбор файла цен (xlsx/xls/csv через `src/shared/spreadsheet.ts`)                    |
| `price-set.service.ts`                                                       | факты для листа (товары, текущие цены площадок) и запись (`plan` / `apply`)          |
| `price-set.module.ts`                                                        | модуль; потребители — `CrmPriceSetModule` и процессор `file-processing`              |
| `src/modules/crm/price-set/`                                                 | kind `price-set:plan`, `POST crm/ym/price-set/upload`, `POST crm/ym/price-set/apply` |
| `web/crm/src/modules/price-set/`                                             | страница `/ym/price-set` (`web/crm/README.md`)                                       |
| `src/modules/yandex/prices/`, `OzonPriceWriteService`, `WbPriceWriteService` | возможность реестра `priceWrite`: чтение текущих цен и запись                        |
| `scripts/preview-price-set.ts`                                               | dry-run «что бы записали», зовёт только `plan`                                       |

## Правила

- **Два способа** (решение `price_set_two_modes`): наценка — свой процент на каждую площадку, площадки
  считаются независимо; файл — одна цена на все выбранные площадки.
- **Наценка — множитель** (решение `price_set_markup_is_multiplier`): 250% = закуп × 2,5. Процент — от 1 до
  10 000 (`isMarkupPercent`), вне границ — опечатка.
- **Закуп — `Product.purchase.price` как есть** (решение `price_set_purchase_raw`): цена из прайса без скидки
  бренда, курса и доп. расходов, не `productCost()`. Наценка без открытой `purchase_prices` — отказ
  (`PriceSetMarkupClosedError`): закупа продавцу не видно, файл остаётся.
- **Цена — целые рубли** (решение `price_set_round_rub`, `Math.round`) на всех площадках.
- **Скидка и зачёркнутая цена не трогаются** (решение `price_set_keep_discount`). ЯМ отправляет текущий
  `discountBase` обратно, пока новая цена в окне 5–99%, иначе не шлёт его (решение `price_set_ym_discount_base`);
  Ozon — без `old_price`; WB — пишется базовая, подобранная под ТЕКУЩУЮ скидку (`wbBasePrice`), «было» на WB —
  цена покупателя (`wbSalePrice`).
- **Неизвестное — не ноль.** Строка без закупа — пропуск `no-purchase`, а не цена 0. Пропуски (`PRICE_SET_SKIP_TEXT`):
  `no-purchase`, `no-card` (товара нет на площадке или в её текущих ценах), `bad-price`, `duplicate` (артикул в
  файле с разными ценами — выпадает целиком). Артикул файла ищется у товара справочника (артикул продавца в
  приоритете, затем артикулы площадок); не нашёлся — берётся как артикул самой площадки.
- **Блокировки — по площадке, независимо** (`PRICE_SET_BLOCK_TEXT`, порядок проверки — порядок перечня):
  `read-error` (текущие цены не прочитались — без них запись запрещена), `no-markup` (для площадки не задан %),
  `no-write-method` (фича записи закрыта — только просмотр, строки всё равно считаются).
- **Риск** (решение `price_set_preview_risky`): |Δ| > 50% (`PRICE_SET_RISKY_DELTA`) или нет текущей цены.
  Сервер только помечает строку; снимает её фронт (по умолчанию), снятые ключи `priceSetRowKey` уходят в `excluded`.
- **WB: право «Цены и скидки» не обязательно** (решение `price_set_wb_prices_scope`): без него чтение — `read-error`
  с понятным текстом, запись — `skipReason: 'no-access'`. Товар с разными ценами размеров не пишется.
- **Выбранная, но не подключённая площадка** (или Ozon/WB с закрытой фичей площадки) в план не входит и
  печатается в `notConsidered` с причиной.
- **Фичи** — все `defaultEnabled: false`:
  - `price_set` открывает раздел `ym-price-set` и план;
  - `price_set_write_ym` (`requires: [price_set]`), `price_set_write_ozon` (`requires: [price_set, ozon]`),
    `price_set_write_wb` (`requires: [price_set, wb]`) — запись своей площадки (`PRICE_SET_WRITE_FEATURE`).
    Кнопка видна, если открыта хоть одна (`priceSetWriteOpen`).

## Барьеры записи — где стоят

1. Гвард маршрута: `@RequireFeature(price_set)` и 403 `WRITE_CLOSED`, если не открыта ни одна `price_set_write_*`.
2. Процессор `file-processing` (`IPriceSetJob`, `source: 'price-set'`) перечитывает запрос плана из результата
   задачи плана по `planJobId`; задачи нет или истекла — «План цен устарел», ничего не записано.
3. `PriceSetService.apply` повторяет проверку фич, пересчитывает план по тому же запросу и пишет только при
   совпадении `planHash` (иначе `PriceSetPlanChangedError`). Пишутся площадки без блокировки, отмеченные
   продавцом, с открытой фичей записи в снимке features, без строк из `excluded`.
4. `priceWrite.writePrices` площадки — единственная функция записи: `PRICE_WRITE_ENABLED=false` (обязательная
   переменная, без умолчания, отдельно от остатков) — dry run без единого запроса; цена не целая или ≤ 0 — отмена
   целиком (`assertPrices`); запросы записи без повторов (`postWrite` ЯМ, `callWrite` Ozon/WB).

Запись — `SYNC_STOCKS` в очередь `file-processing` с `attempts: 1`; идущая запись — 409 `PRICE_SET_RUNNING`.
Каждая записанная площадка оставляет строку `actionlogs` kind `price-set`; сбой чтения — `ErrorReporter`
`price-set:read:<площадка>`, сбой записи — `price-set:write`.

## Доводы и история решений

- **План пересчитывается в процессоре, а не принимается из браузера** — довод «Передачи остатков»
  (`src/modules/stock-push/README.md`): между просмотром и нажатием цену могли поменять в кабинете или обновить
  прайс, и записались бы числа, которых продавец не видел. Отказ стоит одного «Пересчитать», неверная цена в
  чужом кабинете не отменяется ничем.
- **Хранится запрос, а не файл.** Результат задачи плана держит `request` (проценты или строки файла после
  разбора), и `apply` считает план из него: файл повторно не загружается и в Redis не лежит, а отпечаток
  сверяется ровно с тем запросом, что видел продавец. Поэтому `apply` принимает `planJobId`, а не тело плана.
- **Отпечаток — по всему плану без блокировок, а выбор площадок и снятые строки только сужают запись.** Иначе
  отпечаток зависел бы от галочек и снятие строки выглядело бы как «план изменился».
- **План не зависит от фичи записи по строкам:** закрытая запись — `no-write-method`, строки те же, что с
  открытой (довод `stock_push_ozon_wb_same_as_ym`). Отпечаток считает только незаблокированные площадки, так что
  открытие записи между просмотром и нажатием даёт честный «пересчитайте», а не запись невиданного.
- **Своя очередь не заводилась.** Запись цен идёт той же `file-processing` и тем же `@Process`, что прайс и
  остатки: запись в кабинет — одна за раз, второй обработчик сложил бы параллелизм (урок TASK-080).
- **Целые рубли везде.** WB принимает только целые, а одно правило на все площадки не даёт ценам разъехаться на
  копейки.
- **Скидки не придумываем.** Продавец ведёт скидки и зачёркнутые цены в кабинете сам; мы меняем только цену
  продажи. Для ЯМ это значит вернуть текущий `discountBase` — спека снимает его, если не передать.
- **Право WB «Цены и скидки» — вне `WB_REQUIRED_CATEGORIES`**: иначе у подключённых без этой галочки упала бы
  «Проверить связь» и встали бы остатки, заказы и финансы WB.
- **Фронт опрашивает `useJob`, а не `useReportJob`**: записи нужен id задачи плана, а кэш отчётов в браузере
  держал бы план с чужим отпечатком.
- **Живого прогона нет** ни у плана, ни у записи, ни у страницы — `docs/known-gaps.md` (TASK-200…203).
