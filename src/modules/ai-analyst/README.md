# «ИИ-аналитик» (`AiAnalystModule`, TASK-148)

Один ход чата о финансах: история из вкладки → `AiService.completeWithTools` с инструментами `ai-tools` →
ответ, сверка его чисел, ссылки и пробелы данных. Плюс «ИИ-разбор периода» (TASK-150) и еженедельная ИИ-сводка в
Telegram (TASK-168). Вверху — примеры
вызова; правила и причины — ниже, «Доводы и история решений».

```ts
const answer = await analyst.ask({ telegramUserId, aiAllowed, messages }); // purpose по умолчанию 'analyst'
// { answer, verification: {verified, unconfirmed}, sources, gaps, rounds, toolResults, costRub }
// toolResults/costRub — для контрольного набора; CRM их не отдаёт (toView в контроллере)
```

## Контрольный набор вопросов (eval, TASK-169)

**Когда:** вручную, перед сменой `POLZA_AI_MODEL` или правкой промпта (`ai-analyst.domain.ts`) — и после неё,
чтобы сравнить. Прогон **платный** (каждый вопрос — 1–5 запросов к Polza), в CI его нет.

```bash
npx ts-node scripts/eval-ai-analyst.ts --user=<telegramUserId>      # план + оценка ₽, Polza не вызывается
npx ts-node scripts/eval-ai-analyst.ts --user=<telegramUserId> --run # прогон на живом журнале продавца
npx ts-node scripts/eval-ai-analyst.ts --seed --run                  # засеянный PGlite (сентябрь 2026, A1)
#   … --only=1,5 | --grep=casio | --verbose (ответы и вызовы инструментов)
```

- Вопросы — `scripts/eval-ai-analyst.cases.ts`, **одна строка = вопрос**: `{ q, tools, args?, allowClarify? }`.
  Добавить вопрос — дописать строку; `analyst-eval.test.ts` проверит, что инструменты и аргументы существуют.
- Вердикт — `judgeCase` (`analyst-eval.domain.ts`): каждый из `tools` вызван; хотя бы один вызов несёт все
  `args`; ответ не переспрашивает (`asksBack`: «уточните», «какой артикул», вопрос в конце — кроме
  предложений «Хотите…?»); `verifyAnswer` без неподтверждённых чисел. Каждый провал — причиной строкой.
- В `--seed` вопросы к инструментам экранов (прогноз, ДДС, налог, цена, расходы) пропускаются — их сервисов в
  засеве нет; полный набор — только `--user`.
- Отчёт: ✓/✗ по вопросу, причины, раунды, ₽; в конце — сумма по ответам и сумма строк AiUsage `eval` с начала
  прогона (должны совпасть). Код выхода 1 при провалах.

## Качество ответов и 👍/👎 (`AiTurn`, TASK-170)

```ts
await analyst.ask({ ..., turnId });   // turnId передан (ход CRM) — строка AiTurn: счётчики хода
await reviews.review({ ..., turnId }); // то же для разбора; без turnId (eval, сводка) строки нет
// POST /api/crm/ym/ai-analyst/turns/:id/rating          { rating: 'up' | 'down' } — фича ai_analyst
// POST /api/crm/ym/ai-analyst/review/turns/:id/rating   — фича ai_period_review
```

- Счётчики — `turnQualityOf` (`turn-quality.domain.ts`): `numbers` — `checkedNumbers` (тот же список, что
  сверяет `verifyAnswer`), `unconfirmed` — из проверки, `toolCalls`, `rounds`, `asksBackNoTools` =
  `asksBack(answer) && toolResults.length === 0`.
- Оценка — `AiTurnService.rate`: фильтр `{turnId, telegramUserId, purpose}`, чужой/несуществующий/ход другого
  экрана — один 404 `TURN_NOT_FOUND`; `$set` — повтор заменяет.
- Доли — `AiTurnService.quality` (один aggregate, без `eval`) → `GET /api/ai/usage` `quality` → страница «ИИ».

### «ИИ-аналитик» в CRM (M24, TASK-148)

Раздел аккаунта `/ym/ai-analyst` под фичей `ai_analyst` (default off, `requires: [ai, finance]`, решение
`ai_analyst_feature`): чат с вопросами о финансах. Первый вызывающий `AiService.completeWithTools` и
инструментов TASK-147. Ядро — `src/modules/ai-analyst/` (промпт, проверка истории, сверка чисел, ссылки),
доставка — `src/modules/crm/ai-analyst/` (ход в памяти + опрос), фронт — `web/crm/src/modules/ai-analyst/`.
Правила ядра — пункты ниже. `aiAllowed` вызывающий считает из снимка фич сам.

- **Ход живёт в памяти процесса, вкладка его опрашивает** (решение `ai_analyst_in_memory_turns`):
  `POST /turns {messages}` → `turnId`, `GET /turns/:id`. Не crm-jobs: там params и результат сутки лежат
  в Mongo (`CrmJobResult`) и копируются в Redis, а переписка продавца на сервере не хранится (правило
  TASK-104). Не синхронный POST: ход — до пяти запросов к модели, прокси оборвал бы его. Готовый ход
  живёт 10 минут, один идущий на продавца (второй — 409 `TURN_RUNNING` с id идущего, фронт его
  подхватывает). Рестарт ход теряет — вкладка честно просит спросить снова; прод — один инстанс.
- **История — только во вкладке**: фронт шлёт последние 20 реплик, сервер принимает лишь `user`/`assistant`
  (`system` и `tool` из браузера подменили бы промпт или данные, по которым сверяются числа), режет по
  длине со старого конца, вопрос — никогда. Ни журнал CRM (тело не читает), ни `AiUsage` текста не видят.
  Ядро — `normalizeHistory`: последняя реплика — вопрос, до 20 реплик, реплика ≤ 4000 символов, всего ≤ 20 000;
  кривая история — `AnalystHistoryError`.
- **Системный промпт** (`analystSystemPrompt`) — с сегодняшним днём по Москве: числа только из инструментов,
  рубли полем `rub`, без «тыс./млн», «данных недостаточно» вместо догадки, оговорки статуса месяца и закупа.
  Подсказки к инструментам экранов (`GATED_TOOL_HINTS`) — только для видимых модели (TASK-165): набор
  открытых фич приходит из контроллера (`IAnalystAsk.features` ← `AI_GATED_FEATURES` + `isFeatureEnabled`).
- **Каждое число ответа сверяется с данными инструментов ЭТОГО ответа** (решение `ai_analyst_number_check`,
  `verifyAnswer`): из `toolResults` всех раундов — числа `data` (рубли строкой и копейки), счётчики ссылок,
  числа из причин «данных нет». Допуск — единица последнего показанного знака («1 234 568 ₽» ← 1234567.89).
  Не проверяются даты, время, годы, артикулы (`F-91W`), номера пунктов, счёты до 10 и числа из вопроса. Не
  нашлось — `verified: false` и список, ответ показывается с плашкой «не подтверждены», а не прячется: продавец
  видит и ответ, и сомнение.
  Эвристика стартовая, на живых ответах не калибровалась (known-gaps).
- **«Данных недостаточно» печатает экран, а не только модель**: причины `insufficientData` (вызова и
  площадки внутри `compareMarketplaces`) идут отдельным списком `gaps` (`gapsOf`) — модель могла о них промолчать.
- **Ссылки — `sourceRefs` успешных вызовов** (`sourcesOf`: дубли схлопнуты, пустые выброшены): «Операции (N)» раскрывает те же `POST /ym/finance/operations`,
  «В «Финансах»» ведёт на `pnl` с периодом, «Оригинал отчёта» — `documents/:id/original`. Диалог операций и
  его композабл переехали из «Финансов» в `web/crm/src/shared/finance-operations/` — второй потребитель.
- **Отказы**: `AiError` (лимит, фича, ИИ выключен) — `userMessage` без алерта; `PolzaApiError` — его текст,
  репорт уже сделал `AiService`; прочее — `ErrorReporter` (`crm:ai-analyst`). Закрытый `ai` или `finance`
  закрывают раздел гвардом до `AiService` — строк `AiUsage` нет. Ядро ошибки не глотает: `AiError` и
  `PolzaApiError` уходят вызывающему как есть.
- В боте кнопки нет, `featureGate` закрывать нечего.

### Контрольный набор (M26, TASK-169)

- **purpose `eval` пишется в AiUsage, но не входит в дневной лимит продавца** (`AI_EVAL_PURPOSE`, фильтр в
  `spentRubSince`). Прогон на журнале продавца запускает владелец за свой счёт: без исключения 40 вопросов
  съели бы продавцу дневной лимит (50 ₽) и он получил бы отказ в чате; без строки AiUsage стоимость прогона не
  было бы видно на странице «ИИ». Текст вопросов и ответов не хранится — только печатается.
- Набор — данные, а не тесты: вопросы проверяют модель, а не код, ответы недетерминированы и стоят денег.
  Детерминированная часть (оценщик, корректность набора) — в `npm test`.
- `costRub` в ответе — сумма всех раундов: `usage` у `completeWithTools` — только последнего раунда.

### Качество ответов (M26, TASK-170)

- **Своя коллекция `AiTurn` (документ на ход), а не поля на последней строке AiUsage** (решение
  `ai_turn_quality_collection`). Строка AiUsage пишется `void record()` внутри раунда, а счётчики известны
  только после `verifyAnswer` — доапдейт гонялся бы с ещё не вставленной строкой, и turnId пришлось бы тащить
  через `IAiContext` в каждый раунд. Ход CRM в памяти живёт 10 минут, а оценку ставят и позже — владение
  проверяется по документу, не по `InMemoryTurns.view`.
- Текста нет и здесь (правило TASK-104): только числа, флаг и `up`/`down`; тест пинит пути схемы.
- Отдельной фичи у 👍/👎 нет — часть экрана (`ai_analyst` / `ai_period_review`).
- Доли считаются одним aggregate в Mongo (довод `AiUsageService.summary`), контрольный набор исключён — его
  40 вопросов исказили бы долю неподтверждённых. 👎 — от оценённых: неоценённый ход — не «хорошо».
- Разбор без журнала модель не зовёт — строки AiTurn нет, и кнопок оценки нет.
- Скрипт без AppModule (довод diagnose-\*: BotRegistry перевесил бы вебхук); засев — общий с
  `ai-analyst.test.ts` (`__tests__/helpers/analyst-fixture.ts`, без vitest-импортов).
- Регрессия «Casio 18-10-2026» (`ai-tools/README.md`, бренды) — первая строка набора.

### Еженедельная ИИ-сводка в Telegram (M26, TASK-168)

Первое появление ИИ в боте. По понедельникам в 10:00 МСК продавцу с фичей `ai_weekly_digest` (default off,
`requires: [ai, finance]`) приходит разбор прошлой недели пн–вс в 5–7 строк. Ядро — `weekly-digest.{domain,service}.ts`,
доставка — `src/modules/telegram/queue/{processors/weekly-digest.processor,services/weekly-digest*}.ts`.

- **Почему понедельник 10:00.** Неделя закрыта, а ночная загрузка финансов (03:00–05:59) уже положила воскресенье.
  Неделя — московская (`lastFullWeek`): понедельник 00:30 МСК по UTC ещё воскресенье.
- **Почему факты сервера** — те же доводы, что у разбора (`ai_explains_not_computes`): P&L недели и позапрошлой —
  `FinanceService.build` (`flat: false`), статьи — `articleChangesOf` с порогами `REVIEW_THRESHOLDS`, аномалии —
  `FinanceScreenService.anomalies` по месяцам недели (детектор помесячный), убыточные — `lossSkusOf` (топ-5).
  Блоки — общие хелперы `period-review.domain.ts` (`factBlock`, `levelsOf`, `factsPayload`), своей формулы нет.
  Один запрос без инструментов, `purpose: 'weekly-digest'`. Числа ответа — `verifyAnswer` (вопрос несёт даты недели,
  чтобы они не считались выдуманными); неподтверждённые печатаются строкой «Не подтверждены данными», а не прячутся.
- **Нет журнала — сообщения нет.** Хоть один месяц недели не загружен (`months[].status === null`) или операций нет —
  модель не зовётся, строк `AiUsage` нет, в журнал `ActionLog` (`ai-weekly-digest`) — «пропущено: нет данных».
  Неполная неделя на стыке месяцев выглядела бы падением выручки, поэтому тоже пропуск.
- **Отказы ИИ задачу не роняют.** `AiDailyLimitError` → «пропущено: дневной лимит ИИ исчерпан»; прочие `AiError` и
  сбои Polza → «не отправлена: ИИ недоступен» (Polza уже отрепортил `AiService`). Всё прочее — наша поломка, в
  `@OnQueueFailed` своей очереди.
- **Журнал хранит только статус и счётчики**, текста промпта и ответа нет нигде (правило TASK-104, пиннит тест).
- **Админы — только кнопкой** «Отправить сейчас» на «Очередях» (решение `ai_weekly_digest_admins_manual`).

### «ИИ-разбор периода» (M24, TASK-150)

Вкладка «Разбор периода» раздела «ИИ-аналитик» (`/ym/ai-analyst/:tab?`, решение `ai_period_review_tab`) под фичей
`ai_period_review` (default off, `requires: [ai, finance]`). Продавец выбирает месяц и жмёт «Разобрать период». Ответ
говорит, сколько заработано и удержано, какие статьи выросли, что подозрительно, какие товары убыточны и почему
изменились выплаты. К нему идут карточки рекомендаций со ссылками. Ядро — `src/modules/ai-analyst/period-review.*`,
доставка — `src/modules/crm/ai-analyst/crm-ai-period-review.controller.ts`, фронт — вкладка в
`web/crm/src/modules/ai-analyst/`. Правила — пункты ниже.

- **Факты считает сервер, модель их объясняет** (решение `ai_period_review_server_facts`).
  - `periodReviewFacts` (`period-review.domain.ts`, чистая) собирает блоки: итоги месяца и прошлого со сдвигом,
    статьи выше порога, непросмотренные аномалии, убыточные товары и выплаты по статьям — `review:totals`,
    `review:article`, `listAnomalies`, `getSkuEconomics` (убыточные), `review:payouts`, `review:recommendation`,
    `compareMarketplaces`. Все дельты уже посчитаны, модель их не вычисляет
    (`ai_explains_not_computes`).
  - Блок — `IAiToolInvocation` со своими `sourceRefs` (подпись — `sourceRefs.label`). Поэтому `verifyAnswer`, `sourcesOf` и `gapsOf` чата работают и здесь, второй копии
    нет.
  - Модели уходит один запрос без инструментов (`purpose: 'period-review'`): факты уже собраны, и цикл инструментов
    только тратил бы деньги владельца.
- **Рекомендации — кандидаты сервера с метками `R1…`.** Сейчас вид один, `below_min_price`: убыточный товар с
  подтверждённым закупом (`costKnown`, чистая < 0), у которого средняя цена (выручка с возвратами / штуки) ниже
  `minPriceOf`. Формула переехала в `pnl-sku.ts`, реэкспорт
  остался в unit-экономике. Карточки рисуются из кандидатов, а не из текста, поэтому рекомендации без ссылки нет по
  построению. Если модель ставит метку несуществующего кандидата, метка уходит в «не подтверждены», как выдуманное
  число (`verifyReview`). Сравнение площадок кандидата не даёт. Блок площадок — `FinanceService.compare`
  за месяц (TASK-173, та же дверь, что экран и инструмент `compareMarketplaces`): контроллер передаёт открытые фичи
  площадок (`IPeriodReviewAsk.features` ← `AI_MARKETPLACE_FEATURES`), закрытая не читается. Причина закрытой
  площадки или площадки без журнала уходит в пробелы через `compareResult`. Итоги месяца по-прежнему из `build`:
  налог и чистая в блоке площадок — по правилам сравнения, они едут в нём строками `rules`.
- **Числа = «Финансы» по построению.** Итоги берутся из того же `FinanceService.build` (`flat: false`) за месяц и
  прошлый месяц. Тест сверяет выручку, удержания и чистую с P&L до копейки.
- **Почему изменились выплаты — `payoutArticlesOf` (`cashflow.ts`).** Это денежные строки тех же поручений, что
  `payoutsOf`, по статьям, и группировка у них одна (`payoutGroups`). Поэтому Σ равна Σ строк выплат по
  построению. Поле `ICashflow.payoutArticles` добавлено, ДДС и «Обзор» не менялись.
- **Нет журнала за месяц — модель не зовётся вовсе** (`periodReviewFacts` отдаёт строку вместо фактов):
  `answer: null`, причина в пробелах, строк `AiUsage` нет.
  Нет прошлого месяца — прямое «сравнить не с чем», а `change: null` в фактах, не ноль. Если месяц не проверялся
  на аномалии, это пробел, а не пустой список.
- **Ходы — в памяти, по механике чата** (`ai_analyst_in_memory_turns`). `AiAnalystTurns` стал наследником общего
  `InMemoryTurns`, рядом `PeriodReviewTurns`: у каждой вкладки свой «один идущий на продавца». Месяц — текущий или
  12 прошлых (`screenMonths`), иначе 400 `INVALID_MONTH`. Сервис ещё раз отказывает при закрытом `ai`
  (`AiFeatureDisabledError`) до чтения журнала, хотя гвард уже закрыл маршрут.
- **Раздел открыт любой из двух фич** (`CRM_SECTIONS['ym-ai-analyst']`), вкладка видна только со своей фичей
  (`openAiAnalystTabs`). Классовый гвард чата остался `ai_analyst`. В боте кнопки нет, `featureGate` закрывать
  нечего.
- Пороги — один объект `REVIEW_THRESHOLDS` (сдвиг статьи ≥ 1 000 ₽ и ≥ 10 % от прошлого месяца; потолки списков:
  8 статей, 6 статей выплат, 10 убыточных товаров, 5 рекомендаций, 20 аномалий), стартовые
  (known-gaps). `monthLabel` переехал из «Финансов» в `web/crm/src/shared/period`, рядом `recentMonths`.
