# Что не проверено и чем грозит

> Удаляй строку, когда долг закрыт. Сделанное — в сообщениях коммитов.

- **TASK-070, шаг 2 (403 `PASSWORD_CHANGE_REQUIRED` на «любом другом /api/crm/...»)** проверен только
  тестом гварда: других маршрутов CRM пока нет (появятся с TASK-072+). Шаги 1, 3–5 прогнаны curl'ом по
  настоящему HTTP, но на in-memory моделях, а не на `npm run dev` с живой Mongo — `dev` поднимает
  BotRegistry и переставляет вебхук боевого бота. Чем грозит: разница диалекта Mongo — поиск ника
  регэкспом `^…$/i` и upsert с `$setOnInsert` в живой базе не гонялись. Проверить при первом деплое.
- **Ограничитель попыток входа CRM живёт в памяти процесса** (как у админки): рестарт обнуляет
  счётчики, и при нескольких экземплярах приложения у каждого свой.
- **TASK-069, шаг 4 (`docker build .`) не прогнан**: Docker-демон на машине разработки не запущен.
  Прогнана замена: `npm run build` целиком и раздача статики на пустом Nest-модуле теми же вызовами
  `useStaticAssets` — `/crm/` отдаёт CRM, `/` отдаёт админку, `/api` отвечает. Сборке `crm/` из корня нужен
  только `package*.json` (он уже копируется). Чем грозит: опечатка в новых строках COPY всплывёт только
  при деплое. Проверить первым `docker build .` при следующем деплое.
- **TASK-069, шаг 1: шелл CRM глазами не смотрели** — браузерного инструмента в сессии не было.
  Проверено curl'ом: dev-сервер на :5174 отдаёт `/crm/`, модули `main.ts` и `AppShell.vue` собираются;
  `vue-tsc` зелёный. Не проверены вид сайдбара, тёмная тема и выезжающее меню на узкой ширине.
  Чем грозит: вёрстку шелла поправит TASK-071. Открыть `npm run dev:crm` в обеих темах.
- **TASK-071: экраны входа, смены пароля и «Безопасности» глазами не смотрели** — браузерного
  инструмента в сессии снова не было. Проверено: сценарии test_steps по настоящему HTTP через прокси
  `npm run dev:crm` (in-memory модели, не живая Mongo — довод TASK-070), страницы собираются dev-сервером,
  логика гварда/сессии/401 — спеками. Не проверены: вид форм и ошибок у полей, тёмная тема, узкая
  ширина, фактический редирект старой вкладки при возврате на неё (`visibilitychange`). Открыть
  `npm run dev:crm` и пройти шаги 1–3 руками.

- **TASK-072: модель магазина для FBY-гейта CRM берётся только из кэша `YandexMarket.stores`**, без
  живого `listStores` (бот делает фолбэк через `placementFor`). Чем грозит: у FBY-продавца с пустым
  кэшем FBY-экраны CRM ответят 403 «модель определить не удалось». Сейчас FBY-экранов в CRM нет;
  добавить живой фолбэк вместе с ними (TASK-086).
- **TASK-072: сайдбар с закрытой фичей и метка «CRM» в журнале админки глазами не смотрели** —
  браузерного инструмента в сессии не было. Проверено: 403 гейта и строки журнала `source: crm` — по
  настоящему HTTP в `crm-features.test.ts` (in-memory модели), фильтр меню — спекой `visibleNav`.
  Открыть `npm run dev:crm` и панель, пройти test_steps 1–2 руками.
- **TASK-074: фоновые задачи CRM не гонялись на живых Redis и Mongo.** Проверено сквозным HTTP-тестом
  на in-memory моделях с поддельной очередью (процессор вызывается тестом). Не проверены: DI
  `CrmJobsModule` в полном `AppModule` (поднимать его локально = переставить вебхук боевого бота),
  реальный stalled-сценарий Bull и `@OnQueueFailed`, чтение Buffer из настоящей Mongo (приводится
  `Buffer.from`), TTL-удаление. Чем грозит: ошибка DI всплывёт на старте при деплое. Проверить первым
  же запуском после деплоя и `npm run db:sync-indexes` (новые индексы `crmjobresults`).
- **TASK-074: `useJob` глазами не смотрели** — экрана, который его использует, ещё нет (TASK-075+).
- **TASK-075: сверка CRM с ботом на живом магазине не прогнана** (test_steps 1–3). `npm run dev`
  поднимает BotRegistry и переставляет вебхук боевого бота, а без него CRM-задачам не на чем
  выполняться. Проверено: паритет чисел и содержимого xlsx — тестом на реальном
  `OrderReportsService` с заглушкой клиента; отказ глубже 30 дней и уход в архив с флагом — там же.
  Не проверены: DI `CrmOrdersModule` в полном `AppModule` (всплывёт на старте при деплое), размер
  ответа на крупном магазине «Всего» (потолок `MAX_RESULT_BYTES` 15 МБ — строки таблицы не режутся),
  вид экрана (браузерного инструмента в сессии не было: вкладки, выбор дня, тёмная тема, узкая
  ширина). Проверить при деплое: «Едет до клиента» в CRM и в боте в одну минуту, «Выкуплено» за
  вчера с xlsx, «Едет обратно» «Всего».
- **TASK-076: сверка «Прибыли» и «Калькулятора» CRM с ботом на живом магазине не прогнана** (test_steps
  1–2) — довод TASK-075: `npm run dev` переставляет вебхук боевого бота. Проверено: паритет чисел — тестом
  на реальных `ProfitService` + `OrderReportsService` с заглушками клиента и закупа (`crm-profit.test.ts`),
  флаги из снимка и отказ глубже 30 дней — там же; текст бота после выноса хелперов не изменился (тесты
  форматтеров не правились). Не проверены: DI `CrmProfitModule` в полном `AppModule` (всплывёт на старте
  при деплое), вид экрана (браузерного инструмента в сессии не было: столбец вычитаний, таблица sku,
  тёмная тема, узкая ширина). Проверить при деплое: «Прибыль» за месяц в CRM и в боте → одинаковая
  чистая; включить `tariff_calc` → строка калькулятора и вкладка «Калькулятор», разбивка = «Услуги Маркета».
- **TASK-078: «Настройки» CRM на живом магазине не прогнаны** (test_steps 1–3): `npm run dev` переставляет
  вебхук боевого бота. Проверено HTTP-тестом `crm-settings.test.ts` на in-memory моделях: правка из CRM
  видна экрану настроек бота, 403 на продвижение при закрытой фиче, 400 с полем. Не проверены: обратное
  направление (бот → CRM) руками, «Прибыль» с промо по ценам с порогом, вид экрана (таблица скидок,
  диалог продвижения, тёмная тема, узкая ширина). Пройти шаги 1–3 руками.
- **TASK-073: «Профиль» и «Помощь» CRM на живом магазине не сверены с ботом** (test_steps 1–2): `npm run dev`
  переставляет вебхук боевого бота. Проверено: текст `/help`, «Как получить токен» и профиля бота совпадает
  байт в байт с эталонами, снятыми до выноса моделей (`profile-help-model.test.ts`); HTTP-тест
  `crm-profile.test.ts` — поля, админ, отсутствие токена и id магазина, справка == `helpModel()`, 403 до
  смены пароля. Не проверены: DI `CrmProfileModule` в полном `AppModule` (всплывёт на старте), вид экранов
  (браузерного инструмента в сессии не было: вкладки профиля, бейджи функций, списки справки, тёмная тема,
  узкая ширина), имя в CRM берётся из `UserAccess.firstName/lastName` — у продавца, сменившего имя в
  Telegram после заявки, оно разойдётся с ботом (тот читает `ctx.from`). Открыть «Профиль» и «📊 Мой
  профиль», «Помощь» и `/help` для одного продавца и для админа.
- **TASK-077: главная CRM не сверена с отчётами на живом магазине и глазами не смотрена** (test_steps 1–2):
  `npm run dev` переставляет вебхук боевого бота, браузерного инструмента в сессии не было. Проверено спеками:
  kind и период каждой плитки, закрытая фича не ставит задачу и прячет плитку (`report_profit` → прибыли нет),
  сбой одной плитки не трогает соседние, чужое эхо периода → один перезапуск; числа — из тех же задач и мапперов,
  что страницы отчётов. Не проверены: вид сетки плиток и ссылок (тёмная тема, узкая ширина), переход по числу
  в отчёт с периодом из query и снятие query `replace`-ом в живом роутере, нагрузка — главная ставит до четырёх
  задач разом при каждом открытии. Открыть главную и «Отчёты» / «Прибыль» для одного продавца в одну минуту.
- **TASK-079: «Магазины» CRM на живом аккаунте не прогнаны** (test_steps 1–2): `npm run dev` переставляет
  вебхук боевого бота, браузерного инструмента в сессии не было. Проверено HTTP-тестами на in-memory моделях:
  список без токена и идентификаторов, разделы по модели открытого магазина, чужой ключ → 404, отчёт и прайс
  считаются по открытому магазину, а `campaign_id` бота не меняется (`crm-stores`, `crm-jobs`,
  `crm-price-list`), FBY-гейт — по модели открытого магазина, отказ/недоступность Маркета при смене токена
  оставляют прежний токен. Не проверены: DI `CrmStoresModule` и `StoresService` в полном `AppModule`
  (всплывёт на старте), вид экранов (таблица магазинов, форма токена, сайдбар с группой магазина, тёмная
  тема, узкая ширина), автовход при единственном магазине в живом роутере, реальный ответ Маркета на
  перевыпущенный токен. Пройти шаги 1–2 руками на аккаунте с FBS и FBY магазинами.
- **TASK-084: «Платежи» и «Отчёты Маркета» в CRM на живом Маркете не прогнаны.** Шаги 1–2 (xlsx за прошлый
  месяц, «Ключевые показатели» MONTH) проверены только тестами kind-ов поверх настоящих сервисов с клиентом-
  заглушкой: живой `npm run dev` переставляет вебхук боевого бота. Экраны глазами не смотрели (без бэкенда
  `dev:crm` их не нарисует): не проверены вид `OptionGroup` с 8 длинными названиями категорий, тёмная тема,
  узкая ширина. Чем грозит: пути generate шести отчётов до сих пор `v2` «по аналогии» (см. «Четыре экрана» в
  CLAUDE.md) — первый живой запуск в CRM может ответить 404 так же, как в боте. Проверить при первом деплое,
  начиная с «Платежей» и «Ключевых показателей».
- **TASK-087: блок «CRM» на карточке продавца в панели глазами не смотрели** — браузерного инструмента в
  сессии не было. Проверено: шаг 1 сквозным HTTP-тестом `crm-password-reset.test.ts` (обе панели в одном
  приложении, in-memory модели): сброс → старый токен CRM 401 → вход стартовым → смена обязательна, автор

  промахов снимается только в том процессе, который обработал сброс (ограничитель в памяти, см. выше).
  Открыть карточку продавца, сбросить, войти в CRM старой вкладкой.
- **TASK-089/090/091 глазами не смотрели** — браузерного инструмента в сессии не было. Проверено
