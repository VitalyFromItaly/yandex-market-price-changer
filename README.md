# 🤖 Yandex Market Bot

Telegram-бот отчётов по заказам Яндекс.Маркета: сколько уехало клиенту, сколько выкуплено, что едет
обратно и какая с этого чистая прибыль. Плюс обновление остатков из прайса поставщика.

> **Бот почти полностью read-only.** Единственная операция записи в Яндекс — остатки
> (`PUT v2/campaigns/{id}/offers/stocks`). Изменение цен по API прекращено решением заказчика при
> переходе на NestJS: имя репозитория осталось историческим.

## 📊 Что он делает

**Пять отчётов**, каждый — кнопка меню и строка настраиваемой ежедневной рассылки:

| Отчёт | Что показывает |
|---|---|
| 🚚 Уехало клиенту | заказы, отгруженные в службу доставки за период |
| ✅ Выкуплено | заказы, полученные покупателем |
| ↩️ Едет обратно | возвраты и невыкупы |
| 📦 Едет до клиента | всё, что сейчас в пути, файлом `.xlsx` |
| 💰 Прибыль | деньги после комиссии, налога и закупа |

Период выбирается кнопками: сегодня, конкретный день, с начала недели, с 1 числа месяца. Глубина
ограничена самим API — `getOrders` не отдаёт заказы старше 30 дней.

**Прибыль** считается по двум наборам заказов сразу, и это не прихоть: продавец сверяется с
кабинетом, где видит ОФОРМЛЕННЫЕ заказы, а деньги приходят по ВЫКУПЛЕННЫМ. Наборы почти не
пересекаются — сегодняшние заказы выкупят через неделю, — поэтому в отчёте обе цифры и прямая
оговорка, что заказы разные.

```
чистая = продажа − продажа × комиссия% − продажа × налог% − закуп
```

- **Продажа** — товары заказа плюс субсидии Маркета. `itemsTotal` в API это «платёж покупателя», а
  скидку по акции даёт Маркет и продавцу её компенсирует: без второго слагаемого месяц на боевом
  магазине показывал маржу 4 % вместо 22 %.
- **Закуп** — цена из прайса минус согласованная скидка: 4 % по «Востоку», 10 % по остальному.
- Все четыре процента продавец задаёт сам, сообщением: `комиссия: 23`, `налог: 7`, `скидка: 10`,
  `скидка восток: 4`.
- Заказ, по которому закуп известен не полностью, из расчёта выпадает — но отчёт говорит, сколько
  таких и на какую сумму. Возвращённый заказ исключается целиком.

**Остатки.** Продавец присылает боту прайс `.xlsx` документом в чат — кнопки для этого нет. Слово
`проверка` в подписи к файлу включает сухой прогон: остатки в Яндекс не пишутся, но прайс сверяется с
каталогом, а закупочные цены сохраняются в нашу базу. Без этого слова остатки уходят в Partner API.

**Доступ — по одобрению администратора**, а не по подписке. Новый пользователь присылает API-токен,
заявка уходит администраторам, до одобрения бот отвечает только на `/start`. Токена достаточно:
идентификаторы магазина бот определяет сам через `GET v2/campaigns`, а если их несколько — предлагает
выбрать магазин по названию.

## ⚙️ Запуск

```bash
npm install
cp .env.example .env                  # заполнить, см. ниже
docker compose up -d mongodb redis    # mongo :27018, redis :6379, mongo-express :8083
npm run dev                           # nodemon → ts-node src/main.ts
```

Бот работает **через вебхук**, а не long polling, поэтому в разработке нужен публичный URL:

```bash
npm run tunnel        # vk-tunnel на :3004 (или npm run tunnel:ngrok)
```

Полученный адрес — в `TELEGRAM_WEBHOOK_URL`. Обновления приходят на
`POST /api/telegram/webhooks/:type/:id`, вебхук проставляется сам при старте.

Каждый администратор из `TELEGRAM_ADMIN_IDS` должен **сам нажать `/start`**: Telegram запрещает боту
писать первым, иначе карточка заявки не доставится и заявитель будет ждать вечно.

## 🔧 Переменные окружения

Единственный авторитетный список — `src/config/env.validation.ts`; `.env.example` документирует все
ключи. Отсутствующая или неверная переменная роняет приложение на старте с сообщением по-русски, а не
всплывает позже таймаутом соединения.

**Обязательные:**

| Переменная | Смысл |
|---|---|
| `MONGODB_URL`, `MONGODB_DATABASE` | подключение к Mongo |
| `REDIS_HOST` | Redis для очередей Bull |
| `TELEGRAM_TOKEN` | токен бота; из него создаётся первая запись в коллекции `bots` |
| `TELEGRAM_WEBHOOK_URL` | публичный адрес, **на который** Telegram присылает обновления (только при `TELEGRAM_UPDATE_MODE=webhook`) |
| `TELEGRAM_ADMIN_IDS` | numeric id администраторов через запятую |

**С значением по умолчанию:** `PORT`, `NODE_ENV`, `REDIS_PORT`, `YANDEX_MARKET_BASE_URL`,
`TELEGRAM_API_URL`, `TELEGRAM_UPDATE_MODE`. **Необязательные:** `REDIS_PASSWORD` (пусто — без
авторизации), `ADMIN_API_TOKEN` (пусто — журнал действий закрыт для всех).

## 📜 Журнал действий

Каждое действие пользователя пишется в консоль и в коллекцию `actionlogs`: кто (`telegramUserId`
и `@username`), что (команда, кнопка, файл), чем закончилось и сколько заняло. Токен Партнёрского
API и идентификаторы магазина из текста вырезаются перед записью — во время регистрации продавец
присылает токен обычным сообщением. Записи удаляются сами через 90 дней (TTL-индекс).

Чтение — только администратором:

```bash
curl -H "Authorization: Bearer $ADMIN_API_TOKEN" \
     -H "X-Telegram-User-Id: 309809755" \
     'https://<хост>/api/logs?telegramUserId=123456789&limit=50'
```

Параметры: `telegramUserId`, `kind` (`command|menu|callback|document|text|other`), `since`,
`until` (даты ISO), `limit` (максимум 500), `skip`. В ответе — `total` по тому же фильтру.
Незаданный `ADMIN_API_TOKEN` означает «закрыто для всех», а не «открыто без пароля».

> **`TELEGRAM_UPDATE_MODE`: `webhook` (по умолчанию) или `polling`.** Выбор диктуется не удобством, а
> сетевой достижимостью. Вебхук требует, чтобы серверы Telegram могли достучаться до нашего адреса; с
> российского хостинга это не работает — трафик Telegram фильтруется в обе стороны, и `getWebhookInfo`
> отвечает `Connection timed out` при полностью исправном приложении. `polling` разворачивает
> направление: мы сами опрашиваем Bot API через зеркало из `TELEGRAM_API_URL`, то есть по каналу,
> который уже используется для исходящих запросов. Локальной разработке через туннель нужен `webhook`.
>
> Первое, что стоит посмотреть, если бот молчит:
> `curl "$TELEGRAM_API_URL/bot$TELEGRAM_TOKEN/getWebhookInfo"` — поля `pending_update_count` и
> `last_error_message` говорят о доставке больше, чем логи приложения.

> Два «телеграмных» URL смотрят в противоположные стороны и путать их нельзя:
> `TELEGRAM_WEBHOOK_URL` — куда Telegram шлёт запросы нам, `TELEGRAM_API_URL` — зеркало Bot API, куда
> шлём запросы мы (по умолчанию `https://api.telegram.org`). Значение второго должно быть только
> схемой и хостом: telegraf разрешает путь через `new URL('./bot<token>/<method>', apiRoot)`, и
> префикс пути молча потерялся бы.

## 🏗️ Архитектура

NestJS. `src/main.ts` → `NestFactory.create(AppModule)`, глобальный префикс `/api`.

```
src/
├── config/            загрузка и валидация конфигурации (Joi), типизированные геттеры
├── database/          схемы и сервисы Mongoose: Bot, User, UserAccess, ReportSchedule,
│                      PurchasePrice, YandexMarket
├── modules/
│   ├── telegram/      боты, обработчики, очереди Bull   → см. README модуля
│   ├── yandex/        Partner API, отчёты, остатки       → см. README модуля
│   └── parser/        прежний парсер (не используется)   → см. README модуля
├── transport/http/    axios-обёртка прежнего клиента
└── shared/            декораторы и помощники, оставшиеся с до-Nest времён
```

Боты поднимаются через DI: `BotRegistry` читает документы `Bot` из Mongo, создаёт по одному
`Telegraf` на каждый и вешает обработчики. Обработчики — синглтоны, они не хранят экземпляр
`Telegraf`, а получают его в `register(bot)`, поэтому один обработчик обслуживает любое число ботов.

## 🛠️ Команды

```bash
npm run dev            # разработка (nodemon)
npm run build          # nest build → dist/
npm start              # прод: node dist/main.js
npm test               # vitest, 636 тестов
npm run typecheck      # tsc --noEmit
npm run lint           # eslint (0 ошибок, предупреждения есть)
npm run prettier-fix   # prettier --write ./src
npm run api            # перегенерировать неиспользуемый OpenAPI-клиент

npm run db:sync-indexes    # привести индексы базы к схемам (разовая операция)
npm run db:clean           # очистка базы; по умолчанию сухой прогон

# диагностика по боевому магазину, только чтение
npx ts-node scripts/diagnose-orders.ts --user=<telegramUserId> [--report|--unknown]
# закупочные цены из прайса минуя Telegram: пишет только нашу Mongo
npx ts-node scripts/load-purchase-prices.ts --user=<telegramUserId> --file=stock.xlsx
```

CI (`.github/workflows/nodejs.yml`) прогоняет типы, линт, форматирование, тесты и сборку — на push и
на pull request. `--if-present` снят намеренно: отсутствие проверки должно ломать сборку, а не
выглядеть пройденной проверкой.
