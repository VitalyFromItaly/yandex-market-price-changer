**Итог аудита: сквозной пользовательский путь не проходит.** Каркас Nest собран правильно — DI-граф трёх модулей резолвится, Mongoose и 4 схемы живы, 3 очереди Bull с процессорами работают, webhook-роут совпадает с `hookPath` telegraf, `tsc` чист по графу, достижимому из `main.ts`. Но:

- **B1** — схема `YandexMarket` требует `campaign_id/business_id/token`, а код создаёт документ-заглушку с двумя полями → `ValidationError` → `/start` падает у каждого нового пользователя. Ошибку скрывает B3.
- **B2** — метки reply-клавиатуры и `hears`-обработчиков не пересекаются вообще → все кнопки главного меню мертвы, `MenuCommandsHandler` недостижим.
- **B3** — `TryCatch` ловит и возвращает `undefined` без rethrow, навешен на класс целиком → скрывает падения `launch()`, ломает `checkUserSubscription`.

- **B5** — `docker-compose` передаёт `MONGODB_URI`/`REDIS_URL`, код читает `MONGODB_URL`/`REDIS_HOST`/`REDIS_PORT`; `TELEGRAM_TOKEN` не передаётся вообще.
- **B6** — хардкод legacy `parse_mode: 'Markdown'` при тексте с `**bold**` → HTTP 400 → отчёт не доходит.

Плюс: 6 ошибок `TS2307` в осиротевших файлах, `SubscriptionService` фильтрует по несуществующему полю `isActive` (всегда 0 документов), потерянные unique-индексы, ~23 осиротевших файла Express-стека, нулевое покрытие тестами. Главный архитектурный долг — ниже `telegram.service.ts:28` кода NestJS нет, весь слой ботов остался ручным `new`-графом.

**Решения заказчика.** Изменение цен по API прекращаем (код помечаем `@deprecated`, не удаляем, из UI убираем). Бот становится read-only источником отчётов по заказам: уехало клиенту / выкуплено / едет обратно / выгрузка в пути (.xlsx). Каждый отчёт — кнопка плюс настраиваемая ежедневная рассылка. Все три креда обязательны, спрашиваем по одному за шаг. Время всегда MSK. Полная переделка на идиоматичный Nest со своим `BotRegistry` на DI. Осиротевший Express-стек удаляем; сгенерированный OpenAPI-клиент и `CqrsModule` оставляем.

**Находки по Partner API** (сверено с живой документацией — локальный `openapi.yaml` устарел):

- **Версия в пути обязательна**: «Версия указывается в пути URL и является обязательной», «Скоро мы отключим возможность работать с запросами без указания версии». Весь текущий код ходит по неверсионированным путям. `returns` уже на `v2`.
- **Заголовок `Api-Key`**, не `Authorization: Bearer` — поэтому сгенерированный клиент и не использовался. Боту достаточно read-only скоупа.
- **Поправка по суммам**: `total`, `subsidyTotal`, `totalWithSubsidy` deprecated с 22.01.2024; `buyerItemsTotal`, `buyerTotal`, `priceBeforeDiscount` — с 24.06.2024. Актуальная пара: `itemsTotal` и `itemsTotal + deliveryTotal`. Для возвратов — `amount` вместо `refundAmount`, `partnerCompensationAmount` вместо `partnerCompensation`.
- **Окно 30 дней**: `getOrders` не отдаёт данные старше 30 дней, диапазон тоже ограничен 30 днями. Для истории нужен `POST v1/businesses/{businessId}/orders` — это и оправдывает обязательность `business_id`.
- **Лимиты**: orders 10 000 запросов/час, пагинация `pageToken` + `limit` максимум **50** (`page`/`pageSize` deprecated); returns 5 000/час, `limit` до 100.
- **Грабля**: в API существуют **обе** опечатки подстатуса — `DELIVERY_SERIVCE_UNDELIVERED` и `DELIVERY_SERVICE_UNDELIVERED`. Матчить оба, иначе часть возвратов потеряется.

**Как проверено.** Все шесть блокеров подтверждены чтением исходников, а не только выводом агентов: `npx tsc --noEmit` даёт ровно 6 ошибок `TS2307` в трёх осиротевших файлах; расхождение метки клавиатуры и `hears` сверено построчно; `required: true` в схеме сверен с вызовом `create()` с двумя полями; факты по API взяты из официальной документации, ссылки — в `tasks.json` в разделе `reference`.

**Дальше.** Начинать с M0 (`TASK-001`): без рабочей сборки нечего деплоить. Затем M1 — убрать изменение цен, чтобы не тащить мёртвый функционал через рефакторинг. M2 (DI-рефакторинг) намеренно раньше M3–M5, чтобы обработчики онбординга и отчётов писались на целевой архитектуре один раз.
