## 2026-07-28 — TASK-002 (переменные окружения) → done

**Что было.** `docker-compose.yml` передавал `MONGODB_URI` и `REDIS_URL` — имён, которых код не знает. В контейнере это означало `MongooseModule.forRoot(undefined)` и молчаливый уход Bull на `localhost:6379` внутри контейнера. `TELEGRAM_TOKEN` и `TELEGRAM_PROXY_URL` не пробрасывались вовсе. `.env.example` содержал 5 переменных из 9.

**Что сделано.**

- Имена в compose приведены к тем, что реально читает код: `MONGODB_URL`, `MONGODB_DATABASE`, `REDIS_HOST`, `REDIS_PORT`, `PORT`, `YANDEX_MARKET_BASE_URL`. Подключения теперь идут на имена сервисов `mongodb` и `redis`, а не на localhost
- `TELEGRAM_TOKEN` и `TELEGRAM_PROXY_URL` пробрасываются из host-`.env` через `${VAR:?сообщение}` — compose падает с внятным текстом, если их нет. Хардкодить секрет в compose не стал
- `REDIS_PASSWORD` намеренно **не** задан: redis в compose поднимается без auth, а переданный пароль заставлял сервер писать предупреждение на каждое соединение (в логах прошлого прогона их было шесть подряд). После правки предупреждения исчезли
- Убран obsolete `version: '3.8'` — docker на него ругался предупреждением при каждом вызове
- `.env.example` переписан: все 9 переменных, сгруппированы по назначению, с комментариями о неочевидном (почему `MONGODB_URL` без имени базы, зачем 27018, что токен продавца в этом файле не хранится)

**Как проверено.**

- Сверка скриптом: множество `process.env.*` в коде минус ключи `.env.example` = пусто, покрытие полное
- В `.env.example` нет реальных секретов — `TELEGRAM_TOKEN` и `REDIS_PASSWORD` пустые
- `docker compose config` — валиден, все 9 переменных подставляются
- `docker compose up -d --build app` — контейнер поднялся, «Database connection established», Bull инициализировался, бот зарегистрировался. Предупреждений Redis про пароль больше нет
- `curl http://localhost:3000/api` → **200**; `POST /api/telegram/webhooks/:type/:id` → **201** (роут есть, не 404)
- Проверка защиты: с пустым `TELEGRAM_TOKEN` compose падает с `EXIT=15` и сообщением «нужно задать TELEGRAM_TOKEN в .env»

**Замечено, не тронуто.** В локальном `.env` лежат 7 переменных, которые код больше нигде не читает: `ARTEM_YANDEX_MARKET_TOKEN/BUSINESS_ID/CAMPAIGN_ID` (их потреблял вырезанный `testYanndexMarket()`), `PIXABAY_API_KEY`, `UNSPLASH_API_KEY`, `GOOGLE_CUSTOM_SEARCH_API_KEY`, `GOOGLE_CUSTOM_SEARCH_ENGINE_ID`. Чужой файл, не трогал — но их можно смело удалить.

**Состояние окружения.** Контейнер `app` остановлен, `mongodb` и `redis` оставлены поднятыми для следующих задач.

## 2026-07-28 — TASK-001 (сборка) + TASK-003 (чистка Express-стека) → done

**Почему обе сразу.** Начал с `TASK-001`, но на верификации выяснилось, что закрыть её в одиночку нельзя: `npm run build` возвращал **exit 1** из-за шести ошибок `TS2307` в осиротевших файлах, то есть `RUN npm run build` в Dockerfile гарантированно ронял бы сборку образа. `TASK-003` оказалась жёстким предусловием, а не соседней задачей. Обе `critical` и без зависимостей, так что порядок ничего не нарушил.

**TASK-001 — что сделано.**

Помимо описанного в задаче нашлась вторая поломка сборки, которой не было в аудите: в `tsconfig.json` стояло `"rootDir": "."` при `"outDir": "dist"`, из-за чего выход лёг бы в `dist/src/main.js`. То есть даже с исправленным скриптом путь в `start` всё равно не сошёлся бы. Исправлено на `"rootDir": "src"`.

- `nest-cli.json` — новый, `tsConfigPath` указывает на `tsconfig.build.json`, `deleteOutDir: true`
- `tsconfig.build.json` — новый, расширяет основной и исключает тесты
- `package.json`: `build` → `nest build` (было `ts-node src/main.ts`, то есть запуск вместо компиляции); `start` → `node --enable-source-maps dist/main.js`; `start:prod` → `build && start` (раньше собирал дважды)
- `Dockerfile` переписан на двухэтапный: builder с devDependencies собирает `dist`, runner получает только прод-зависимости и `dist`. `ts-node` из рантайма ушёл

**TASK-003 — что сделано.**

Перед удалением проверил точным грепом по `from '...'`, что внешних импортов нет (первый прогон грепа был слишком широким и ловил подстроки — `index`, `UserService` внутри `TelegramUserService`; перепроверил по путям).

Удалено: `src/controllers/`, `src/routes/`, `src/middleware/`, `src/services/UserService.ts`, `src/modules/telegram/bots/shared/services/user-subscription.service.ts` (домиграционный дубль `TelegramUserService`), `BaseScene.ts`, `BaseService.ts`, 0-байтные `src/types/main.d.ts` и `src/modules/yandex/index.ts`.

Отдельно: `typeRoots` в `tsconfig.json` был объявлен неверно — указывал на **файлы** вместо директорий (`["src/types/main.d.ts", "src/types/express/index.d.ts"]`). В таком виде он ломал резолв `@types` из `node_modules`. Убран целиком, восстановлено поведение по умолчанию.

**Как проверено.**

## 2026-07-28 — Аудит и постановка бэклога

Составлен план переделки и заведён локальный бэклог: `tasks.json` (34 задачи, M0–M7), `tasks.archive.json`, этот журнал. Полный план — в `/Users/vitalijperekutnev/.claude/plans/reactive-launching-turing.md`.

**Итог аудита: сквозной пользовательский путь не проходит.** Каркас Nest собран правильно — DI-граф трёх модулей резолвится, Mongoose и 4 схемы живы, 3 очереди Bull с процессорами работают, webhook-роут совпадает с `hookPath` telegraf, `tsc` чист по графу, достижимому из `main.ts`. Но:

- **B1** — схема `YandexMarket` требует `campaign_id/business_id/token`, а код создаёт документ-заглушку с двумя полями → `ValidationError` → `/start` падает у каждого нового пользователя. Ошибку скрывает B3.
- **B2** — метки reply-клавиатуры и `hears`-обработчиков не пересекаются вообще → все кнопки главного меню мертвы, `MenuCommandsHandler` недостижим.
- **B3** — `TryCatch` ловит и возвращает `undefined` без rethrow, навешен на класс целиком → скрывает падения `launch()`, ломает `checkUserSubscription`.
- **B4** — `"build": "ts-node src/main.ts"` запускает приложение вместо компиляции → `dist/main.js` не существует → прод по факту идёт через ts-node.
- **B5** — `docker-compose` передаёт `MONGODB_URI`/`REDIS_URL`, код читает `MONGODB_URL`/`REDIS_HOST`/`REDIS_PORT`; `TELEGRAM_TOKEN` не передаётся вообще.
- **B6** — хардкод legacy `parse_mode: 'Markdown'` при тексте с `**bold**` → HTTP 400 → отчёт не доходит.

Плюс: 6 ошибок `TS2307` в осиротевших файлах, `SubscriptionService` фильтрует по несуществующему полю `isActive` (всегда 0 документов), потерянные unique-индексы, ~23 осиротевших файла Express-стека, нулевое покрытие тестами. Главный архитектурный долг — ниже `telegram.service.ts:28` кода NestJS нет, весь слой ботов остался ручным `new`-графом.

**Решения заказчика.** Изменение цен по API прекращаем (код помечаем `@deprecated`, не удаляем, из UI убираем). Бот становится read-only источником отчётов по заказам: уехало клиенту / выкуплено / едет обратно / выгрузка в пути (.xlsx). Каждый отчёт — кнопка плюс настраиваемая ежедневная рассылка. Все три креда обязательны, спрашиваем по одному за шаг. Время всегда MSK. Полная переделка на идиоматичный Nest со своим `BotRegistry` на DI. Осиротевший Express-стек удаляем; сгенерированный OpenAPI-клиент и `CqrsModule` оставляем.

**Находки по Partner API** (сверено с живой документацией — локальный `openapi.yaml` устарел):

- **Версия в пути обязательна**: «Версия указывается в пути URL и является обязательной», «Скоро мы отключим возможность работать с запросами без указания версии». Весь текущий код ходит по неверсионированным путям. `returns` уже на `v2`.
- **Заголовок `Api-Key`**, не `Authorization: Bearer` — поэтому сгенерированный клиент и не использовался. Боту достаточно read-only скоупа.
- **Поправка по суммам**: `total`, `subsidyTotal`, `totalWithSubsidy` deprecated с 22.01.2024; `buyerItemsTotal`, `buyerTotal`, `priceBeforeDiscount` — с 24.06.2024. Актуальная пара: `itemsTotal` и `itemsTotal + deliveryTotal`. Для возвратов — `amount` вместо `refundAmount`, `partnerCompensationAmount` вместо `partnerCompensation`.
- **Окно 30 дней**: `getOrders` не отдаёт данные старше 30 дней, диапазон тоже ограничен 30 днями. Для истории нужен `POST v1/businesses/{businessId}/orders` — это и оправдывает обязательность `business_id`.
- **Лимиты**: orders 10 000 запросов/час, пагинация `pageToken` + `limit` максимум **50** (`page`/`pageSize` deprecated); returns 5 000/час, `limit` до 100.
- **Грабля**: в API существуют **обе** опечатки подстатуса — `DELIVERY_SERIVCE_UNDELIVERED` и `DELIVERY_SERVICE_UNDELIVERED`. Матчить оба, иначе часть возвратов потеряется.

**Как проверено.** Все шесть блокеров подтверждены чтением исходников, а не только выводом агентов: `npx tsc --noEmit` даёт ровно 6 ошибок `TS2307` в трёх осиротевших файлах; расхождение метки клавиатуры и `hears` сверено построчно; `required: true` в схеме сверен с вызовом `create()` с двумя полями; факты по API взяты из официальной документации, ссылки — в `tasks.json` в разделе `reference`.

**Дальше.** Начинать с M0 (`TASK-001`): без рабочей сборки нечего деплоить. Затем M1 — убрать изменение цен, чтобы не тащить мёртвый функционал через рефакторинг. M2 (DI-рефакторинг) намеренно раньше M3–M5, чтобы обработчики онбординга и отчётов писались на целевой архитектуре один раз.
